# 성경2PPT 작업 이력

> godpia 성경 검색 보완 및 사용자 요구사항(테마/파일·DB 정보/오프라인 저장 버튼/DB 편집기/버전 관리) 구현 이력.
> 대상: `Bible2PPT_SRC_2.1.0/Bible2PPT-main` (현재 리포지토리).

---

## 1. 작업 목표

1. 전체 소스코드를 분석하여 **프로젝트 구조** 파악 (Visual Studio project → 파일별 구조화, 세부 내역 정리).
2. 전체 코드를 분석하여 **기능 명세서**를 리버스 엔지니어링.
3. **godpia 성경 검색** 기능을 보완 (현재 `http://bible.godpia.com`이 사라져 검색 에러).
4. **사용자 추가 요구사항** 구현:
   - 설정 메뉴에 **테마 선택**(다크/라이트, 아이콘).
   - 설정 메뉴에 **생성 파일·DB 파일명/크기** 표시.
   - **오프라인 저장 버튼** 높이 확보(글자 잘림 수정).
   - 좌측 메뉴 **DB 아이콘**(PPT 제작 기록 아래)으로 **DB 편집기** 구현(서역/장/구절 표시, 구절 편집, 저장(다른이름), 복원, 리비전/버전 관리, 잘못된 DB 읽기 방지).
   - **상세 기능 명세서 + 작업 이력** 문서화.

---

## 2. 작업 순서 (단계별)

### Step 1 — 구조 파악
- `README.md`, `CHANGELOG.md`, `LICENSE`, `Bible2PPT.sln` 리뷰.
- 7개 프로젝트(`Bible2PPT`, 4개 Services, 2개 Tests)와 각 `MainForm.*.cs` 부분 클래스를 파일별로 매핑.
- `MainForm.Designer.cs`의 좌측 메뉴(`historyNavButton`, `templatesNavButton`, `settingsNavButton`, `dbNavButton`)와 각 `MultiPanelPage`(`historyMultiPanelPage`, `templatesMultiPanelPage`, `settingsMultiPanelPage`, `dbMultiPanelPage`) 구조 확인.
- `Theme.cs`(`AppTheme`, `ThemeManager`), `DarkTheme.cs`, `LightTheme.cs`, `AppConfig.cs`, `BinaryConfig.cs`, `DbFileService.cs` 리뷰.
- **결론**: godpia 엔드포인트는 `http://bible.godpia.com`을 가리켜 에러. 새 사이트는 `https://www.godpia.com`. 설정 페이지는 `InitializeSettingsComponent()`가 빈 상태(구현 미흡).

### Step 2 — godpia 실측 (엔드포인트 검증)
- 임시 프로젝트(`ProbeRef`)로 실제 godpia API 호출:
  - `GET https://www.godpia.com/read/reading.asp?ver=gae` → 책 목록 HTML (정상, 200).
  - `GET https://www.godpia.com/read/reading.asp?ver=saenew&bible=신12:1` → 200 + HTML (검색 엔드포인트 동작 확인).
- **발견**: 엔드포인트 자체는 정상. 기존 `GodpiaBible`이 `bible.godpia.com`(삭제된 도메인)을 가리켜 에러.

### Step 3 — godpia 소스 교체/보완
- `GodpiaBible.cs`의 `BaseUrl`을 `https://www.godpia.com`으로 변경.
- 3개 엔드포인트(`/read/reading.asp`, `/include/asp/chapinfo.asp`, `/read/reading_body.asp`) + 정규식(`BookPattern`, `ChapterPattern`, `VersePattern`)을 신규 사이트에 맞춘다.
- **합쳐진 구절 처리**: 개역개정(4판)의 range 번호(`dataSec="18-19"`)를 `VersePattern`에서 매칭하고 `ParseVerseNumber`로 첫 번호를 반환 → 누락 방지.
- `BibleService.GetVersesAsync`에 `MergedVerseFirstNumber` 딕셔너리로 **합쳐진 구절 장 재추하** 로직 추가(`IsMergedVerseChapter`, `MergedVersePresent`, `ReplaceChapterVersesAsync`).
- `GetBooksOnlineAsync`/`GetChaptersOnlineAsync`의 `OrderBy Number` 정렬, `HttpClient` 타임아웃 30초 설정.

### Step 4 — 설정 페이지 구현 (신규)
- `MainForm.Settings.cs`:
  - **테마 선택**: `IconButton` 두 개(다크=`IconChar.Moon`, 라이트=`IconChar.Sun`), `SetTheme`/`HighlightActiveThemeButton`, `AppConfig.Context.Theme` 저장 + `ThemeManager.Apply`.
  - **파일·DB 정보**: `TextBox`(read-only)에 DB 파일명/크기/리비전/저장시간 + 템플릿 파일명/크기 표시(`UpdateFileInfo`, `HumanizeSize`).
  - **생성 파일 추가 표시**: PPT 제작 기록(`Builder.GetJobs()`)에서 **최근 2건**의 생성 대상 경로(파일 또는 장별 출력 폴더)를 실제 존재 확인 후 `파일명(크기)` 또는 `폴더명(총크기, N개)`으로 표시. 없으면 `(없음)`. (`DescribePptOutput` 추가, `using System.Linq`).
  - 기존 `[업데이트]`, `[캐시 청소]` 핸들러 유지. 템플릿 표시 문구 `_Template_` → `템플릿`으로 수정.
  - **컴파일 오류 수정**: 초기 `readonly` 필드 → 일반 필드로, `IconChar.MoonCrescent/Sunrise` → 실제 존재하는 `IconChar.Moon/Sun`으로 (reflection로 1459개 멤버 중 확인).

### Step 5 — 오프라인 저장 버튼 높이 수정
- `MainForm.Build.cs`의 `_offlineSaveButton.Height`을 글자 잘림이 사라질 때까지 증가시킴. 최종 **38**으로 설정 (인접 `DB 편집` 버튼도 38으로 통일).
  - "오프라인 저장" 텍스트가 잘리는 현상이 보고되어, 충분한 높이 확보를 우선시했다.

### Step 6 — DB 편집기 구현 (신규, 좌측 메뉴 DB 아이콘)
- `MainForm.Db.cs`의 `InitializeDbComponent()`로 **DB 편집 화면** 구성:
  - 상단 도구바: `[새로 불러오기] [다른 이름으로 저장] [복원]` + DB 정보라벨.
  - 번역 `ComboBox`, 3단 ListView 트리(책/장/절).
  - 하단 구절 편집기(`TextBox` + `[이 구절 저장]` 버튼).
- `DbFileService.cs`에 **버전 관리** 기능 추가:
  - `ValidateDbFile`/`ValidateActiveDb`: SQLite 마기 헤더 + `integrity_check` + `Bibles` 테이블 존재(3단계) 검증.
  - `ReadDbMeta`/`ReadActiveMeta`: `DbMeta` 테이블의 마지막 리비전.
  - `SaveDbAs`: `DbMeta` 테이블 생성/확보 → `revision = MAX+1` → meta 기록 → `{userBaseName}_{yyyyMMdd_HHmmss}_r{D4}.db` 파일 복사.
  - `RestoreDbFile`: 선택 파일을 **활성 DB 위치**로 복사 + meta 반환 (복원 전 검증으로 **잘못된 DB 읽기 방지**).
- `MainForm.Designer.cs`에 좌측 메뉴 **DB 아이콘**(`dbNavButton`, `IconChar.Database`)을 **PPT 제작 기록 아래** 추가.

### Step 7 — 빌드·테스트·문서화
- `dotnet build Bible2PPT.sln -c Debug` → **오류 0, 경고 0**.
- `dotnet test` → **21/21 + 1/1 통과 (실패 0)**.
- `docs/기능_명세서.md` (기능 명세), `docs/작업_이력.md` (본 문서) 작성.

### Step 8 — GitHub API 기반 버전관리 (2026-11-20)
- **요청**: GitHub 저장소에서 현 작업 내역 및 버전관리를 위해 GitHub API 키 사용.
- **대상 저장소**: `metalsky/Bible2PPT`
  - 제공된 API 키 소유계정은 `metalsky`. 원본 저장소(`sunghwan2789/Bible2PPT`)에는
    이 키의 push 권한이 없음(`push: false`) → `metalsky/Bible2PPT` 포크를 버전관리 대상.
- **전수 상태 확인**: 원격 tree(`/git/trees/HEAD?recursive=1`) vs 로컬 워크트 비교
  - 원격(2.0.4, 2022-05-12, .NET Framework 4.8) 파일 **114개** / 로컬(2.1.0-dev, .NET 8) 파일 **126개**
  - 변경 8개, 신규 118개, 원격에만 존재 106개 (2.1.0-dev는 .NET 8 리팩토링으로 파일 구조 자체가 변경)
- **실행**:
  1. API 키 인증으로 저장소 clone
  2. 로컬 현 작업 소스 + `docs/` 3개 문서 + `CHANGELOG.md` + `README.md` + `build-activity.log`
     (빌드 활동 기록 원문 = 작업 내역 원문)를 워크트와 동기화
  3. 단일 커밋으로 `main` push — 커밋: `feat(v2.1.0): 갓피아 성경 검색 보완, DB 편집기, 테마,
     파일·DB 정보 표시, 세부 문서화(기능명세/작업이력/개선안) 및 GitHub API 버전관리`
  4. REST API로 태그 `v2.1.0` 및 릴리스(리리즈 노트 포함) 생성
- **제외 내용**: craft 런타임 파일(`feed.json`, `craft.json`, `usage.json`, `inbox/`,
  `attachments/`, `capture/`, `investigation.cany/`), 빌드 산출물(`bin/`, `obj/` — `.gitignore` 관리)
- **검증**: REST API 커밋 목록(`/repos/.../commits`), 릴리스 목록(`/releases`),
  tree(`docs/` 존재) 확인으로 push·태그·릴리스 반영 확인.
