# 성경2PPT 기능 명세서

> 성경 구절(PPT 소스: 갓피아 등)을 검색·캐시하여 PowerPoint(.pptx)로 생성하는 WinForms 프로그램의 기능 명세.
> 대상 버전: 현재 리포지토리(`Bible2PPT_SRC_2.1.0/Bible2PPT-main`).

---

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 앱 이름 | 성경2PPT |
| **버전** | **2.1.1** (GitHub 태그 `v2.1.1`, 저장소 `metalsky/Bible2PPT`) |
| 플랫폼 | Windows, WinForms (.NET 8.0-windows) |
| PPT 엔진 | Microsoft PowerPoint 2007+ (Office interop) |
| DB | SQLite (에디터용 성경 DB, `bible-v3.db`) |
| 성경 소스 | 갓피아(`GodpiaBible`), 갓피플(`GodpeopleBible`), GOODTV(`GoodtvBible`) |
| 테마 | 다크 / 라이트(`ThemeManager`, `DarkTheme`, `LightTheme`) |
| 설정 | `app.config`(`BibleContext` 연결 문자열) + 실행 파일 옆 `.cfg`(`AppConfig`/`BinaryConfig`) |

## 3. 핵심 기능 명세

### 3.1 성경 검색 (godpia 중심)

**목적**: 선택된 소스에서 성경/장/구절을 가져와 캐시(에프.에.에.엔.T SQLLite `bible-v3.db`)에 저장하고, PPT 생성 시 활용한다.

**검색 카스케이드 (소스 → 캐시 → PPT)**

```
선택 소스(BibleSource)
 └─ GetBiblesAsync   → 캐시(이전) 또는 online GetBiblesOnlineAsync → 캐시 기록
 └─ GetBooksAsync    → 캐시 또는 online GetBooksOnlineAsync
 └─ GetChaptersAsync → 캐시 또는 online GetChaptersOnlineAsync
 └─ GetVersesAsync   → 캐시 또는 online GetVersesOnlineAsync
    └─ (합쳐진 구절 장이면) online 재추하(신6:18-19, 시92:1-3 등)
```

**godpia 엔드포인트** (`https://www.godpia.com`, `GodpiaBible`)

| 단계 | 엔드포인트 | 매개변수 | 반환 |
| --- | --- | --- | --- |
| 번역 목록 | (내부 정의) | - | 8개(개역개정4판, 개역한글, 쉬운성경, 현대인의성경, 새번역, NIV, 히브리어, 헬라어) |
| 책 | `GET /read/reading.asp` | `ver={translation_code}` | HTML → 책(`gen`, `exo`, …) |
| 장 | `GET /include/asp/chapinfo.asp` | `ver={ver}&vol={book_code}` | HTML → 장 번호 |
| 구절 | `GET /read/reading_body.asp` | `ver={ver}&vol={book_code}&chap={chapter}` | HTML → 각 절(`<li dataSec="N">`) |

**주요 구현 특징**
- `GodpiaBible.cs`는 3개 정규식(`BookPattern`, `ChapterPattern`, `VersePattern`)으로 HTML을 파싱한다.
- `VersePattern`는 range 번호(`dataSec="18-19"`)까지 매칭하여 `ParseVerseNumber`가 range 첫 번호(18)를 절 번호로 반환 → 합쳐진 구절 누락 방지.
- `BibleService.GetVersesAsync`는 캐시가 없으면 online, 캐시가 있어도 **개역개정(4판) 합쳐진 구절 장**에서 `MergedVerseFirstNumber`가 존재하고 캐시에 해당 구절이 없으면 online 재추하 후 캐시 교체(`ReplaceChapterVersesAsync`)한다.
- **검색 입력 칸**(`booksSearchTextBox`)은 선택한 소스의 책 목록을 **클라이언트 사이드**로 필터링(전문 prefix 매칭)하며, 장/절은 트리(ComboBox/ListView)로 탐색한다.

**검색 안정화(이번 작업의 보강)**
- 갓피아 홈페이지 재설치로 기존 `http://bible.godpia.com`이 사라졌던 문제를 신규 도메인 `https://www.godpia.com` + 위 3개 엔드포인트로 교체.
- **정적 파서 분리**: 파싱 로직(`ParseBooks`, `ParseChapters`, `ParseVerses`)을 `GodpiaBible`의 static 메소드로 분리 → 네트워크 없이 HTML 픽처로 **단위 테스트 가능**.
- **HTTP 재시도/백오프**: `GetStringWithRetryAsync`로 최대 3회 재시도, 지수적 백오프(1초→2초), `HttpClient` 타임아웃 30초. 재시도 초과 시 기존 UI 재시도 다이얼로그와 호환되도록 **`WebException`**을 던진다.
- 엔드포인트는 실제 호출로 검증(200 + 정상 HTML).
- `OrderBy Number` 정렬, `LinkForeigns`로 실체 참조 연결(`book.Bible`, `chapter.Book`, `verse.Chapter`) — `GetChaptersOnlineAsync`/`GetVersesOnlineAsync`는 이 참조를 이용해 `ver`/`vol`/`chap` 쿼리 파라미터를 구성한다.

### 3.2 PPT 생성

- **템플릿**(`.pptx`): `AppConfig.TemplatePath`(기본 `_Template.pptx`) 또는 사용자 선택.
- **치환자**: `[TITLE]`, `[STITLE]`, `[CHAP]`, `[PARA]`, `[BODY]`, `[BODY1]`~`[BODY9]`, 실험용 `[CPAS]`, `[CPAE]`.
- **장별 저장**: `책 이름/장 번호.pptx` 구조로 장별로 .pptx를 저장.
- **행수 기준 슬라이드 분할**: 템플릿 행 수 제한 내에서 슬라이드를 나누고, 비어있는 페이지는 넘긴다.
- **동기화/동기화**: `Builder`(`BuildService`)에서 PowerPoint interop을 통해 슬라이드를 생성/채우며, 진행 상태와 취소 지원.

### 3.3 오프라인 캐시

- 처음에 구절을 online으로 받아 **DB(`bible-v3.db`)에 저장**하면, 이후는 인터넷 없이 PPT를 만들 수 있다.
- `app.config`의 `BibleContext` 연결 문자열이 DB 경로를 결정한다(`DbFileService.ActiveDbPath`).
- **캐시 청소**: 설정 페이지의 `[캐시 청소]` 버튼은 DB를 삭제(`ClearCachesAsync`) 후 `Application.Restart()`로 재시작한다.
- **업데이트**: `[업데이트]` 버튼은 `AppConfig.ContactUrl`(GitHub)로 열려 최신 버전을 안내한다.

### 3.4 테마 선택 (다크/라이트) — **신규**

**위치**: 좌측 메뉴 **설정**(`settingsNavButton`, `IconChar.Cog`) → 설정 페이지.

| 제어 | 설명 |
| --- | --- |
| `다크` 버튼 | `IconChar.Moon`(흰색) |
| `라이트` 버튼 | `IconChar.Sun`(노란색) |
| `생성 파일 & DB` 정보창 | DB/템플릿 파일명·크기, 리비전·저장시간 |

**동작**
1. 버튼을 누르면 `SetTheme(AppTheme.Dark|Light)` 호출.
2. `AppConfig.Context.Theme = theme` → `AppConfig.Context.Save()`(`.cfg` 파일에 1바이트 저장).
3. `ThemeManager.Apply(this)`로 메인 폼 컨트롤 트리 전체에 해당 테마 색상을 재귀적 적용(`DarkTheme.Apply` / `LightTheme.Apply`).
4. 선택된 버튼의 `FlatAppearance.BorderColor`를 `Accent(0,120,212)`로 강조.
5. 시작 시 `InitializeSettingsComponent()`에서 저장된 테마를 읽어서 자동으로 반영.

**색상 팔레트**
- `LightTheme`: Background(248), Surface(255), Text(32), Accent(0,120,212), FieldBorder(190), Selection(217,233,255).
- `DarkTheme`: 반대(어두운 배경/밝은 텍스트), `Accent` 공통.
- `AppConfig.Theme`은 `AppTheme` enum(Dark=0, Light=1), `ThemeManager.Current` 프로퍼티로 접근.

### 3.5 생성 파일 & DB 정보 표시 — **신규**

**위치**: 설정 페이지 하단, `TextBox`(read-only, multiline).

**표시 내용**
```
생성 PPT: <최근 생성 PPT 파일명>(<크기>)
DB: bible-v3.db (4.5 MB)
  리비전: v3 (2026-11-20 15:23)
템플릿: _Template.pptx (1.2 MB)
```
- **생성 PPT**: PPT 제작 기록(`Builder`의 Job)에서 **최근 2건**의 생성 대상 경로가 실제로 존재하면 표시.
  - 단일 파일인 경우 `파일명 (크기)`.
  - 장별로 나눠 저장한 **폴더**인 경우 `폴더명 (총크기, N개)`.
  - 존재하지 않으면 `생성 PPT: (없음)`.
- DB 파일이 없으면 `DB: (파일 없음)`을 표시.
- 크기는 `HumanizeSize`(B/KB/MB, 1024 기준)로 포맷.
- DB 파일 경로: `app.config`의 `BibleContext` `Data Source`(없으면 실행 파일 옆 `bible-v3.db`).

### 3.7 DB 편집기 (좌측 메뉴 DB 아이콘) — **신규**

**진입**: 좌측 메뉴, **PPT 제작 기록(`historyNavButton`) 아래**에 **DB 아이콘**(`dbNavButton`, `IconChar.Database`)을 추가 → `MainForm.Db.cs`의 `dbMultiPanelPage`에 DB 편집 화면 표시.

**화면 구성**
- **상단 도구바**: `[새로 불러오기] [다른 이름으로 저장] [복원]` + DB 정보라벨(`DB: bible-v3.db (4.5 MB) | v3 (2026-11-20 15:23)`).
- **번역 선택**: `ComboBox`(DropDownList), 저장된 모든 번역(서역) 목록.
- **3단 트리**: 좌측 `책`(이름, 장 수), 중부 `장`, 우측 `절`(번호, 본문 첫 45자 trunc).
- **하단 구절 편집기**: 선택한 구절의 본문은 `TextBox`(multiline, 12pt)에 표시, `[이 구절 저장]` 버튼으로 `BibleService.UpdateVerseText`를 통해 DB에 기록.

**동작**
1. **새로 불러오기**: `DbFileService.ValidateActiveDb()` → SQLite 마기 헤더 + `integrity_check` + `Bibles` 테이블 존재 검증 후 `BibleService.GetStoredCatalog()`로 번역/책/장을 로드.
2. **번역/책/장 선택**: 트리 갱신(`UpdateDbBookLists`, `DbBooksList_SelectedIndexChanged`, `DbChaptersList_SelectedIndexChanged`).
3. **장 선택 시 구절 로드**: `BibleService.StoredVerses(chapterId)`로 DB의 구절을 비동기로 로드(27ms 이하, 27ms 이하).
4. **구절 편집**: 텍스트 수정 시 `(수정됨)` 표시 → `[이 구절 저장]`으로 `UpdateVerseText` 저장, 목록에 반영, `MessageBox` 알림.

### 3.8 DB 저장(다른이름) / 복원 / 리비전 관리 — **신규**

**저장(다른이름)** — `[다른 이름으로 저장]`
1. `NameInputForm`으로 새 이름 입력.
2. `DbFileService.SaveDbAs(name)`:
   - `DbMeta` 테이블(`Revision INTEGER PRIMARY KEY, SavedAt TEXT, FileName TEXT`) 생성/확보.
   - `revision = MAX(Revision)+1`.
   - 활성 DB에 meta 행을 **기록**한 뒤, **동일 시간/리비전**의 새 파일로 복사.
   - **파일명**: `{userBaseName}_{yyyyMMdd_HHmmss}_r{D4}.db` (예: `mybible_20261120_152345_r0003.db`).
   - 성공 시 `MessageBox`로 `이름 / 리비전 / 저장시간` 알림.

**복원** — `[복원]`
1. `OpenFileDialog`로 DB 파일 선택.
2. `ValidateDbFile`으로 유효성 검증(마기/무결성/Bibles 테이블).
3. 선택 파일의 `DbMeta`(리비전/저장시간/이름)를 `MessageBox`로 확인 → 사용자 동의.
4. `RestoreDbFile(sourcePath)`: 선택 파일을 **활성 DB 위치로 복사** → `ReloadDbPageAsync()`.
   - 잘못된 DB(마기 불일치, 무결성 손상, Bibles 테이블 부재)는 **복원 전**에 차단 → **잘못된 DB가 읽히는 위험 방지**.

**리비전/버전**
- `DbMetaInfo`: `Revision`(int, auto-increment), `SavedAt`(DateTime), `FileName`.
- 저장/복원 시 `Revision`이 증가하며, 파일명/메타에 `저장시간 + r{li}`가 기록되어 **리버티/복원 이력 추적** 가능.
- 설정 페이지와 DB 편집기에서 **현재 DB의 파일명/크기/리비전/저장시간**을 동일하게 표시.

## 4. 설정 (app.config / AppConfig)

| 항목 | 저장처 | 값 |
| --- | --- | --- |
| `BibleContext` (SQLLite 연결 문자열) | `app.config` | `Data Source={DB경로};Version=3;` → DB 경로 결정 |

> `app.config`의 `BibleContext` 연결 문자열은 **비밀값으로 취급**되며, 문서화 시 절대 포함하지 않는다.

## 5. DB 스키마 (SQLite, `bible-v3.db`)

| 테이블 | 목적 |
| --- | --- |
| `Bibles` | 번역(서역) |
| `Books` | 책 |
| `Chapters` | 장 |
| `Verses` | 구절(`Text` 포함) |
| `DbMeta` | 저장 리비전/시간/이름(`Revision`, `SavedAt`, `FileName`) |

- `DbFileService.ValidateDbFile`: **3단계** 검증 — ① SQLite 마기 헤더(16바이트) ② `PRAGMA integrity_check` ③ `Bibles` 테이블 존재 → `Bibles` 테이블이 없으면 "성경 DB가 아님"으로 거부.

## 7. 알려진 한계 / 참고

- **godpia 검색은 클라이언트 사이드 책 필터 + 트리 탐색**이며, "전체 성경 본문 키워드 검색"이 아니라 **책→장→절 탐색** 형태다.
- godpia `reading_body.asp`는 **장 전체**를 반환하므로, 특정 **구절 번호로만** 검색하는 API는 제공되지 않는다.
  - **합쳐진 구절(range, 예: `dataSec="18-19"`)**은 개역개정(4판)에서 2~3개의 절을 하나의 `<li>`로 제공한다. 파서는 range의 **첫 번호**로 단일 구절로 저장하며, PPT 범위가 해당 range에 오버플랩하면 해당 구절이 빠지지 않도록 `MergedVerses.VerseInRange`로 판별한다(신6:19, 시92:2-3 등 요청 시 합쳐진 18절/1-3절 텍스트를 반환).
- 테마 적용은 **WinForms 컨트롤 트리**에 적용되며, PowerPoint 내부 슬라이드 테마는 템플릿에 따라 달라진다.
- `DbEditForm.cs`(기존 DB 편집 화면)는 새 DB 편집기(`MainForm.Db.cs`)와의 공존·대체 관계는 향후 정리 필요.
